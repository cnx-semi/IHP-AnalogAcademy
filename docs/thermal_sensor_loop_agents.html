What changed in v2: the target is the Croc SoC (/home/attapon/cnx-semi/croc). I read its RTL, user domain, flow scripts and docs. Five findings change this design:

  1. Bus is OBI, not OBI. Croc's interconnect is OBI v1.6; the user domain hands you an OBI subordinate port. The register block becomes an OBI subordinate (decision D10).
  2. Croc's process is sg13cmos5l by default (CMOS only: Metal1–4 + TopMetal1, no SiGe HBT). The npn13G2 probe from v1 does not exist there; the substrate PNP pnpMPA does (decision D11).
  3. The course ADC uses cap_cmim (MIM caps, 22 uses in module 3); sg13cmos5l has no MIM in its models, only cap_cmomi (MOM) and MOS caps. The C-DAC must be re-done with MOM caps.
  4. A GDS needs a real analog layout. Croc's GDS flow merges standard cells and SRAM macros; an analog macro needs LEF + GDS + LVS netlist and edits to several flow scripts. Layout is now in scope (decisions D9, D13).
  5. The flow is long: place and route about 2.5–3 h, signoff DRC about 2 h, so Croc judges run at gates, not every round.
  6. Your baseband direction (lots of digital logic): both Croc process variants use the same standard cells, and the open 130 nm IHP PDK has nothing denser. More logic comes from the 7-layer metal stack of sg13g2, die size and utilization (stock Croc is only 44 % core-utilized). That moves my D11 recommendation to sg13g2, gated by a baseline run (D11, Phase 0).

One correction to what I said in chat. I said a 10-bit ADC gives about 0.25 °C per LSB. That assumed the whole code range maps to temperature. With the ratiometric scheme recommended here, -40..125 °C only occupies about 20–27 % of the code range, so a 10-bit ADC gives about 0.6–0.8 °C per LSB and a 12-bit ADC about 0.15–0.2 °C. See decision D1.

1. What we are building

A small mixed-signal macro that measures die temperature and exposes it to the processor over OBI, with a hardware over-temperature alarm, placed in the user domain of the Croc SoC. Process: IHP 130 nm; Croc defaults to SG13CMOS5L (decision D11). Tools: the course's open-source analog flow (xschem, ngspice/Xyce, KLayout, Verilator, Icarus) plus Croc's digital flow (Yosys, OpenROAD, KLayout).

Why ratiometric

The probe produces V_PTAT = α·ΔVBE (proportional to absolute temperature) and V_REF = VBE + α·ΔVBE (about a bandgap voltage). The ADC converts μ = V_PTAT / V_REF. Because V_REF is also the ADC reference, absolute reference accuracy cancels and temperature is a linear function of the code: T[K] ≈ A·μ. The price is that only part of the code range is used (section 8, D1).

6.4 Behavioral rules (digital)

  • Reset (rst_n low) clears all registers except ID; sensor disabled until EN.
  • START while BUSY is ignored; DONE sets when averaging completes; IRQ = IRQ_EN & (OT_HI | OT_LO).
  • OBI: gnt in the cycle after req when idle; one outstanding transaction; read data on rvalid, err=0 for every address inside the 4 KB slot (unmapped offsets read 0, writes ignored); addresses outside go to Croc's own error subordinate.
  • irq is level-sensitive and connects to interrupts_o[0]; software clears the sticky flags with W1C writes.

7.3 Escalation protocol

A reviewer that finds a trade-off (not a bug) returns:

DECISION: ESCALATE
QUESTION: <one sentence>
OPTIONS:  A) <option, cost>   B) <option, cost>
RECOMMEND: <A|B and why>
BLOCKS: <what cannot proceed until answered>

The conductor appends that to DECISIONS-NEEDED.md, pauses only that branch (other squads continue), and asks you. Your answer is written back into CONTRACT.md by you or by the conductor on your instruction, never by a designer.

7.4 Reviewer reject list (what "gaming" means here)

  1. Judge script, postprocess_adc.py, CONTRACT.md thresholds or test temperatures changed after baseline.
  2. Test sweep narrower than the contract (temperature, supply, corners, ramp span, conversions per code).
  3. Ideal or behavioral element standing in for a real one without a PROGRESS.md note.
  4. Any edit under modules/** or the PDK.
  5. Bit order, full scale, threshold arguments changed without justification.
  6. An integrator edited a block file, or a block designer edited an integration file.

8. Human decisions I need from you

Each decision has options, my recommendation, and what it changes. Say accept all, or give me the numbers you want to change. D10–D13 are new in v2 and D3, D9 and D11 changed because of Croc and your baseband direction.

D1. ADC resolution and what "resolution" means

With ratiometric μ spanning about 0.2–0.27 of full scale over -40..125 °C:

OptionSingle-conversion resolutionCost
A) 10-bit SAR≈ 0.6–0.8 °C/LSBcourse blocks reused with 2 more bits; INL at 10 bit is within reach of a unit-cap C-DAC
B) 12-bit SAR≈ 0.15–0.2 °C/LSB4× capacitor area, tighter matching, likely needs calibration
C) 10-bit + offset subtraction (shift the window)≈ 0.25–0.35 °C/LSBextra analog block in the sensor, more error terms
Recommend A. Thermal throttling and monitoring rarely need better than 1 °C steps. Sensor accuracy (about ±1.5 °C trimmed) is the limiter anyway. Keep averaging in digital for noise. Revisit B/C only if you need sub-0.5 °C steps.

D2. Reference scheme

A) ratiometric (ADC reference = VREF from the probe) — B) absolute (a separate bandgap + ADC against it).

Recommend A. Fewer blocks, supply and reference errors cancel to first order, and it is the classic approach for BJT sensors. Cost: part of the code range is unused (D1).

D3. Supply domain for sensor and ADC

On Croc the core supply is 1.2 V (pad_vdd0) and the I/O ring has its own supply (pad_vddio*, 3.3 V-class pads; to confirm). VREF ≈ 1.2 V needs headroom. A) everything on the 1.2 V core rail with a scaled VREF (about 0.6 V, α adjusted) — B) analog on the I/O supply with level-shifters at the digital boundary (needs extra pads, see D12).

Recommend A for v1 if the sensor squad confirms the 0.6 V scaling works; fallback B. I have not confirmed which supply the course's bandgap uses; the sensor squad's first action is to read modules/module_1_bandgap_reference and report. This is the least certain analog item in the document.

D4. Accuracy targets and trim

±3.0 °C untrimmed and ±1.5 °C with a one-point trim (register TRIM). Trim happens in software or at test; the macro stores nothing non-volatile.

Recommend as stated. If you need ±1 °C untrimmed the sensor must add dynamic element matching and chopping; that is a different, larger project.

D5. Sample rate and clocking

100 S/s required; clock input 100 kHz–1 MHz after divider; conversion = bits + 2 cycles.

Recommend as stated. Slow clock makes settling and power trivial and lets the course's comparator and switches work unchanged.

D6. Hardware over-temperature alarm

Include THRESH_HI, THRESH_LO, sticky flags and an irq pin, or leave alarm to software polling.

Recommend include. About 40 lines of RTL; it is the feature a thermal sensor exists for.

D7. Where code-to-°C conversion lives

A) software does T = A·code + B — B) a hardware multiplier/adder returns Q8.2 °C.

Recommend A for v1. Keeps the register block small and the contract simpler; B is a clean follow-up.

D8. Number of probes

A) one probe in v1 — B) N probes through an analog mux sharing one ADC (true "thermal probing" of several die sites).

Recommend A for the first loop run, with a parameter N_PROBES reserved in the register map (CTRL bits). Mux settling and charge injection add an integration problem we should not mix with learning the loop.

D9. Layout and physical verification (now required for a GDS)

Croc's goal is a GDS, so the analog macro needs a real layout. A) schematic-level blocks and a placeholder macro in Croc first (LEF with correct pins and area, empty or box GDS) — proves the flow, the OBI interface and software, then real layout as a separate gated project — B) layout from the start.

Recommend A, then B as Phase 5. A placeholder macro lets the Croc loop (L1, L2) run in parallel with analog design and exposes flow-script problems early. Real layout then gets its own loop and judges (DRC, LVS, extraction, post-layout sweep), reusing the repo's flows that already run.

D10. Bus protocol of the register block

A) native OBI subordinate — B) keep AXI4-Lite and add an OBI↔AXI-Lite bridge — C) APB behind Croc's obi_to_apb.

Recommend A. Croc's user domain is OBI; the tree contains obi_to_apb and apb_to_obi but no AXI-Lite bridge (I checked rtl/obi and rtl/*.sv), so B means importing another PULP IP and verifying it. Your original AXI-Lite wish is better served later by exporting the same register map behind a wrapper if another SoC needs it.

11. How it runs in Claude Code (and limits)

  • Agent files are Markdown with frontmatter (name, description, tools, model) in .claude/agents/; the body is the system prompt. A new session picks them up.
  • The conductor is a slash command in .claude/commands/. It runs in your main session and calls agents by name.
  • Limit: subagents cannot call other subagents (as far as I know in the current version). So squads are not "lead agents that manage workers"; the conductor drives every squad. The hierarchy in the chart is logical, not nested processes.
  • Parallelism: the conductor can start the three Phase-1 builders in the same step, each in its own worktree. Verifiers then run in parallel as well.
  • Unattended mode: a shell script can run one claude -p "/loop-block adc" per squad (process-level hierarchy), collect each squad's verdict file, then start integration. Use this for overnight runs; the stop rules live in code.
  • Hard guarantees: a Stop hook can refuse to end a session while a judge fails; a PreToolUse hook can block edits outside an agent's scope. I would add these after the first manual runs.
  • Two shells: the analog tools (/opt/tools/analog/env.sh) and the Croc flow (croc/env.sh, its own PDK_ROOT logic) must not be sourced together; every judge starts in a clean subshell for its own environment.
  • Cross-repo work: the croc-integrator works in a git worktree of Croc, so the stock Croc checkout and its generated GDS stay reproducible.
  • Cost control: round caps (section 7.2) bound the worst case; cheap models (haiku) run the verifier; the strongest model is used only for review.
